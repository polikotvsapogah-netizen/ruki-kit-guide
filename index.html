1. Что это и для кого

Кит рук ставит на вашу машину сборку, на которой работает конвейер рук. Кит доставляет сборку, а работает сама сборка: Orca, Claude Code, Codex, omp, скиллы Матта Покока, скиллы Orca и скиллы кита.

Рука (синоним: воркер) это отдельная сессия модели. Рука исполняет один тикет в своём worktree по конверту и сдаёт координатору кандидата. Координатор ведёт волну: выбирает процесс, раздаёт тикеты рукам, принимает кандидата, вливает его и закрывает тикеты.

Для кого: для админа, который ведёт работу тикетами в GitHub и хочет отдавать код тикетов рукам параллельно, с ревью, гейтом и живой проверкой после мержа.

Что даёт сборка

  • Конвейер рук

    Волна рук по тикетам на полосах opus, astra и glm: конверт, кандидат, ревью, гейт, мерж.

  • goodRun

    Цепочка от конца грилинга до итоговой таблицы без ручных пересадок между вкладками.

  • Механизм контекста

    Ступени контекста, самосжатие, хуки сжатия, чекпоинт по слову и автоперенос.

  • Скиллы и конвейер

    Команды кита и порядок конвейера Матта Покока: какой скилл на какую задачу.

Где можно встрять

Сборка под Windows не проверена. Три звена под Windows остаются гипотезами спеки: Orca на Windows открывает вкладки в WSL2, wslpath переводит путь worktree из ответа Orca, надзор снимает всех потомков руки внутри WSL. Первая волна под Windows скорее всего упадёт на одном из пунктов отладки. Логи этой волны приложите к тикету отладки, который завёл владелец кита.

Нужны свои подписки и входы. Кит их не даёт. Обязательны Claude Code с входом, gh с входом для трекера и Orca для вкладок. Codex и omp необязательны: без них полосы astra и glm выключены.

Скиллы ставятся из сети. Скиллы Матта Покока и скиллы Orca /ruki:setup берёт свежими из репо авторов через npx. Без сети эти пункты не встанут.

С чего начать

  1. Инструменты и входыПоставьте Claude Code, gh, Orca, по желанию Codex и omp, и войдите в каждый. Под Windows ставьте их внутри WSL2: раздел 2.
  2. ПлагинПрочитайте права ролей. Затем выполните claude plugin marketplace add <орг>/ruki-kit и claude plugin install ruki@ruki-kit.
  3. Проверка сборкиНаберите /ruki:setup в сессии Claude Code и отвечайте y или N по строкам отчёта check: как читать отчёт.
  4. Конфиг получателяНазовите setup штаб, владельца GitHub и трекер: setup запишет их командой ruki-setup install config KEY=value .... Команду тестов гейта FR_GATE_CMD допишите в конфиг сами: ключи конфига.
  5. Проверочная волнаНаберите /ruki:fable-ruki-agenty с одним тикетом. Под Windows это отладочная волна: что приложить к тикету отладки.

Сборка: набор инструментов и скиллов, с которым работает кит. Команда /ruki:setup сверяет машину с этой таблицей и по каждому недостающему пункту печатает команду установки.

3. Установка

Установка идёт в три шага: права ролей, две команды плагина и диалог /ruki:setup.

Windows: сборка требует отладки. Кит живёт в Claude Code внутри WSL2. Orca на Windows открывает вкладки в WSL, штаб и репо рук лежат в файловой системе WSL. Фразы «работает под Windows» без живого прогона нет.

Пункты отладки для админа:

  • Orca создаёт worktree рук в WSL и возвращает путь; wave-launch.sh читает путь из ответа и путь Windows переводит через wslpath;
  • вкладки goodRun и автопереноса открываются в WSL;
  • надзор снимает руку по потолку времени и убирает всех её потомков;
  • хуки контекста пишут state-файлы;
  • пин автосжатия действует в новой сессии.

Проверочную волну запускайте через wave-launch.sh, а не ручным git worktree add. К тикету отладки приложите вывод ruki-setup check, журналы событий попыток рук и лог гейта первой волны.

Права ролей: прочитайте до установки

  • рука opus: claude -p --dangerously-skip-permissions из worktree руки;
  • рука astra: codex exec --sandbox workspace-write с записью в worktree, его git-каталоги и FR_STATE;
  • рука glm: omp -p с набором инструментов и --add-dir штаба и FR_STATE;
  • goodRun ③ Astra: codex exec --sandbox danger-full-access из корня репо;
  • вкладки goodRun ④ и ⑤: claude --dangerously-skip-permissions из корня вашего штаба;
  • ревью Astra: codex exec в detached-копии кандидата.

Worktree задаёт рабочий каталог и не ограничивает доступ к файлам. Ставьте кит на машину без живых контуров и без данных, которые нельзя терять.

macOS и Linux

claude plugin marketplace add <орг>/ruki-kit
claude plugin install ruki@ruki-kit

<орг>: владелец репо кита на GitHub. Хуки механизма контекста подключает сам плагин, ваш settings.json остаётся нетронутым.

Windows через WSL2

  1. В PowerShell администратора выполните wsl --install.
  2. Перезагрузите машину.
  3. Внутри WSL поставьте Claude Code, gh, zsh, node, по желанию codex и omp.
  4. Внутри WSL войдите в каждый CLI: claude, gh auth login, codex login.
  5. Положите штаб и репо рук в файловую систему WSL, а не под /mnt/c: там git работает медленно.
  6. Выполните две команды установки из блока macOS и Linux и затем /ruki:setup. Первая строка отчёта setup напомнит про отладку.

Что делает /ruki:setup

Скилл ведёт диалог, а работу делает скрипт bin/ruki-setup. Скрипт выполняет одну команду и выходит:

ruki-setup check
печатает строку на пункт и итог; код выхода 0, если все обязательные пункты на месте, иначе 1.
ruki-setup install <пункт>
ставит один пункт; программы ставит человек: скрипт печатает команду и выходит кодом 3.
ruki-setup rollback <пункт>
возвращает последнюю копию пункта байт в байт; без копии печатает «копии нет».

Строка отчёта check имеет вид <статус> <пункт>: <что даёт>; установка: <команда>. Статусы: ok, нет и предупреждение. Строка с отступом поясняет пункт над ней: пропавшее имя скилла или выключенный вход $goodrun. Последняя строка несёт итог.

Как отвечать y или N

  • По каждой строке нет и каждой строке предупреждение с командой ruki-setup install setup задаёт один вопрос y или N.
  • Ответ y запускает ruki-setup install <пункт>. Ответ N печатает команду установки из отчёта.
  • Код выхода 3 значит «ставит человек»: setup печатает команду, и программу ставите вы.
  • Каждая правка вне каталога плагина печатает строку откат: ruki-setup rollback <пункт> (копия <путь>). Установщик ничего не изменил: строка «изменений нет».
  • Предупреждения hooks-double и slow-git setup показывает без вопроса: их правите вы.
  • Если Codex есть, setup спрашивает ещё два пункта: плагин кита в Codex и скиллы Матта Покока в Codex.
  • В конце setup повторяет check и показывает итог и оставшиеся строки нет.

Откат любой правки: ruki-setup rollback <пункт>. Правки вне каталога плагина идут только по ответу y, копии лежат в ~/.config/ruki/rollback/<пункт>/.

Обновление, удаление, установка из ZIP

claude plugin update ruki@ruki-kit
claude plugin uninstall ruki@ruki-kit

Во время goodRun и волны кит не обновляйте: новая вкладка грузит установленную версию, а работающая сессия остаётся на своей. После удаления конфиг получателя и пин остаются: их снимает ruki-setup rollback <пункт>.

Архив ZIP подключается на одну сессию командой claude --plugin-dir <zip>. Для постоянной установки распакуйте архив и добавьте каталог локальным маркетплейсом: claude plugin marketplace add <каталог>, затем claude plugin install ruki@ruki-kit.

Документация: плагины Claude Code, Codex.

4. Роли и модели

Координатор ведёт волну, руки пишут код тикетов, ревьюер проверяет кандидата по риску. Модели и лимиты ниже подставлены из кода кита при экспорте.

Координатор: Fable (/ruki:fable-ruki-agenty) или Opus (/ruki:opus-ruki-agenty, запасной вход, когда лимит Fable исчерпан).

Полосы рук

Тег при входе выбирает полосу: без тега работает opus, тег astra выбирает astra, тег glm выбирает glm. При обоих тегах работает glm.

ПолосаМодель и effortCLIЛимит рук
opus, без тегаclaude-opus-5-5 highclaude -p3
astra, тег astragpt-6-astra mediumcodex execбез лимита обвязки
glm, тег glmzai/glm-5.3-flash, worker-onlyomp -p2

Потолок времени руки по умолчанию: 45m на любой полосе. Потолок конверта: 40 КБ; конверт больше потолка режет тикет до волны.

Кто ещё работает

  • Ревьюер Astra high: пакетное ревью кандидата, когда риск его требует. Без риска кандидата проверяет сам координатор.
  • Запасной ревьюер: Opus по подписке через REVIEWER=opus-headless, когда Astra недоступна.
  • Роли goodRun: ③ Astra high ревьюит грилинг и архитектуру; ④ Fable max пишет спеку и тикеты; ⑤ координатор Fable high ведёт волну.
  • Субагент итога ruki:goodrun-itog собирает таблицу стадий goodRun: модели, время, попытки, токены.

5. Цикл волны рук

Волна: один заход конвейера рук по тикету или пакету тикетов под одним координатором. Волна кончается закрытием её тикетов.

  1. Вход: вы набираете /ruki:fable-ruki-agenty или /ruki:opus-ruki-agenty, тег выбирает полосу.
  2. Выбор процесса: координатор соразмеряет процесс с тикетами: малую правку делает сам, остальное отдаёт рукам.
  3. Конверт: цель, AC, разрешённые файлы, швы с соседними тикетами, исходный SHA, проверки и адрес результата. Рука не видит контекста координатора.
  4. Рука работает в своём worktree, который создаёт Orca, и держит потолок времени.
  5. Кандидат: запушенная ветка с SHA и докладом по каждому AC.
  6. Пакетное ревью отдельным ревьюером, если риск его требует; иначе кандидата проверяет сам координатор.
  7. Приёмка координатора: AC всех тикетов по проверкам, отчёту ревью и разбору находок.
  8. Гейт: полный прогон проверок на итоговом дереве. Изменённое дерево требует нового гейта.
  9. Мерж допускает только зелёный гейт на том же дереве.
  10. Выкат один на волну, штатным путём контура.
  11. Живой DoD: проверка на работающем контуре фактом живого состояния, а не тестом.
  12. Закрытие тикетов с маркером результата.

6. goodRun

/ruki:goodrun ведёт цепочку от конца грилинга до итоговой таблицы без ручных пересадок между вкладками.

  • ① Грилинг: вы и агент прорабатываете задачу до решений.
  • ② Старт: /ruki:goodrun вырезает диалог грилинга и открывает вкладку следующей стадии.
  • ③ Astra high ревьюит грилинг и архитектуру. Первая попытка идёт сразу, следующие после пауз 180, 300, 600 с. Потолок одной попытки 2700 с. Серия исчерпана: пауза цепочки, вкладка ждёт Enter, стадия ④ не стартует.
  • ④ Fable max пишет спеку и тикеты по ответу Astra.
  • ⑤ Координатор Fable high ведёт волну рук по тикетам.
  • ⑥ Итог: субагент ruki:goodrun-itog собирает таблицу «стадия, модель, время, попытки, токены».

Вход из Codex: грилинг идёт в Codex, вы набираете $goodrun. Стадия ③ пропускается, вкладка Fable max открывается с промптом ④к.

Без Codex /ruki:goodrun останавливается до вкладки Astra и печатает ручной путь: /to-spec, /to-tickets, /ruki:fable-ruki-agenty.

7. Контекст и чекпоинт

Механизм контекста держит длинную сессию в рабочем состоянии и не теряет адреса работы при сжатии. Автоматический чекпоинт здесь называется чекпоинтом перед сжатием, а весь приём называется самосжатием.

Самосжатие

  • Ступени контекста 280000, 330000, 380000 токенов: хук hooks/hq-context-pause.py советует довести текущий этап до законченного результата. Совет, а не запрет: ход не блокируется.
  • Чекпоинт перед сжатием: команда scripts/compact-ready.py пишет файл состояния сессии (сделано, следующий шаг, открытые вопросы, адреса) и разрешает сжатие в том же окне. Руки при этом могут работать: их ветки, SHA и pid идут в файл состояния.
  • Хук до сжатия пропускает сжатие только по свежему чекпоинту: цикл совпадает, файл не менялся. Без чекпоинта сжатие откладывается до следующего запроса.
  • Хук после сжатия дописывает адреса в файл состояния. Сессия читает файл и продолжает ту же задачу.
  • Пин автосжатия: функция claude в профиле шелла ставит окно автосжатия 313000 токенов. Пин действует в новой сессии, запущенной командой claude.

Потолок сжатий и автоперенос

Потолок сжатий: 4 на сессию. После потолка сессия пишет чекпоинт остановки: хэндофф в .handoff/, комментарий в Issue и промпт продолжения. Затем идёт автоперенос: скрипт scripts/session-respawn.py поднимает сессию-продолжение той же моделью и с тем же effort и гасит сессию-родителя. Автоперенос идёт один раз на цепочку; дальше решаете вы.

Чекпоинт по слову

  • Слово «чекпоинт» или команда /ruki:checkpoint готовит перенос работы в новое окно: доставка работы, хэндофф в .handoff/ репо сессии, комментарий в Issue и промпт продолжения в чат.
  • Слова «завершаем сессию» закрывают работу: доставка, запись в Issue и промпт в чат, хэндоффа нет.
  • Новое окно по слову само не открывается. Откройте сессию и начните её словами «Продолжаем чекпоинт»: хук hq-checkpoint найдёт хэндофф и погасит его.
  • Чекпоинт по слову требует точку чекпоинта: работа доставлена, ничего не в полёте. Протокол целиком лежит в docs/agents/session-end.md.

Какой скилл на какую задачу

Хук конвейера на старте сессии в код-репо один раз предлагает ветку по проверяемому признаку задачи. Процессом рулит человек: хук предлагает, а не запускает.

  1. Грилинг (/grill-me, /grill-with-docs): решения по вопросам, пока нельзя назвать файлы и признак готовности.
  2. /to-spec: спека в трекере, когда результатов два и больше или меняется контракт.
  3. /to-tickets: тикеты по швам спеки.
  4. Руки: /ruki:fable-ruki-agenty ведёт волну по тикетам.

Место goodRun: после грилинга /ruki:goodrun заменяет ручные шаги 2…4 и добавляет ревью Astra перед спекой. Скиллам /to-spec, /to-tickets и /triage нужен один запуск /setup-matt-pocock-skills в репо и трекер с входом.

9. Словарь

Термины кита. Тот же словарь лежит в ките файлом docs/glossary.md.

Рука
отдельная сессия модели, которая исполняет тикет волны в своём worktree по конверту координатора и сдаёт координатору кандидата. В речи владельца то же понятие зовётся «воркер»; в текстах штаба пишем «рука».
Сборка
набор инструментов, моделей и скиллов, на котором работает конвейер рук: Orca, Claude Code, Codex, omp, скиллы Матта Покока, скиллы Orca и скиллы штаба.
Кит рук
приватное репо ruki-kit, из которого сборку рук ставят на другую машину. Кит доставляет сборку, а работает сама сборка.
Волна
один заход конвейера рук по тикету или пакету тикетов под одним координатором: конверты, руки, кандидат, приёмка координатора, гейт, мерж, выкат и живой DoD. Волна кончается закрытием её тикетов.
Координатор
сессия модели, которая ведёт волну и отвечает за её результат: выбирает процесс, раздаёт тикеты рукам, принимает кандидата, вливает его и закрывает тикеты. Код тикетов пишут руки, координатор сам делает только малую правку.
Полоса
маршрут, по которому волна запускает руки: модель, её CLI и лимит одновременных рук. Полосу выбирает тег при входе в режим; без тега работает полоса по умолчанию.
Конверт
самодостаточное задание руке на один тикет: цель, AC, разрешённые файлы, швы с соседними тикетами, исходный SHA, проверки и адрес результата. Рука не видит контекста координатора и работает только по конверту.
Кандидат
результат, сданный на проверку и ещё не влитый в ствол. Кандидат руки: запушенная ветка с SHA и докладом по каждому AC. Кандидат пакета: дерево, которое координатор собрал из ствола и веток рук.
Пакетное ревью
один проход отдельного ревьюера по кандидату пакета до мержа: требования, стандарты, AC всех тикетов, стыки и затронутые риски. Его заказывают по риску; без риска кандидата проверяет сам координатор. После коррекции проверяют только дельту.
Приёмка координатора
решение координатора, что кандидат пакета выполняет AC всех тикетов, по проверкам, отчёту ревью и разбору находок. Руку на коррекцию возвращает только подтверждённый блокер. Приёмка координатора идёт до гейта и не заменяет приёмку владельца.
Гейт
полный прогон проверок целевого репо на итоговом дереве пакета перед мержем. Мерж допускает только зелёный гейт на том же дереве; изменённое дерево требует нового гейта.
Живой DoD
проверка DoD тикета на работающем контуре после мержа и одного выката волны, фактом живого состояния, а не тестом. Для работы без выката в тикет записывают причину, по которой выкат неприменим.
Ступень контекста
значение контекста сессии, на котором хук советует планировать или делать перенос. Числа ступеней задаёт хук hooks/hq-context-pause.py, глоссарий их не повторяет. Совет, а не запрет: ход не блокируется, вызовы не отклоняются.
Ступень волны
шаг цепочки зависимых тикетов волны. Цепочка из N зависимых тикетов идёт N ступенями волны (skills/fable-ruki-agenty/references/workflow.md, раздел «Подготовка и исполнение», п.5). Слово «ступень» без уточнения неоднозначно: пиши «ступень волны» или «ступень контекста».
Точка чекпоинта
момент, в который перенос безопасен: работа доставлена, результаты фоновых агентов собраны, нет действия A3 в ожидании kk, ничего не в полёте с живым состоянием. Точку выбирает модель, порог только советует.
Чекпоинт перед сжатием
запись текста состояния командой scripts/compact-ready.py. Запись разрешает сжатие в том же окне. Точка чекпоинта для неё не нужна: руки могут работать, их адреса (ветки, SHA, pid и handle) идут в файл состояния сессии.
Чекпоинт по слову
перенос работы по слову владельца по протоколу docs/agents/session-end.md: доставка, хэндофф, промпт продолжения. Чекпоинт по слову требует точку чекпоинта, а чекпоинт перед сжатием её не требует.
Файл состояния сессии
файл ~/.local/state/hq-context-pause/focus/<sid8>.md. Файл пишет чекпоинт перед сжатием (compact-ready), адреса после сжатия дописывает хук PostCompact, хук PreCompact сверяет его sha256 с записью готовности. Файл состояния сессии не заменяет фокус волны.
Фокус волны
фокус-файл координатора волны: цель, решения, AC, модели, SHA, очередь merge, handles рук и следующий шаг. Фокус волны ведёт координатор, хуки контекста его не читают.
Автоперенос
механический перенос сессии в новое окно после потолка сжатий, один раз на цепочку (чекпоинт по слову владельца его не зовёт, решение владельца 14.09.2026): скрипт scripts/session-respawn.py поднимает сессию-продолжение той же моделью и с тем же effort, отдаёт ей промпт из хэндоффа и гасит сессию-родителя после признака жизни продолжения.

Журнал сбоев

Журнал сбоев лежит в скилле fable-ruki-agenty кита: skills/fable-ruki-agenty/references/incidents.md. Каждая запись несёт три части: событие → причина → правка или тикет. Новые записи идут сверху. Волна без сбоев пишет строку «сбоев нет» с датой.

Уроки по симптомам

Форма урока: симптом, причина, что делать.

  1. Рука вышла с кодом 0, а доклада нетМодель закончила ход последним сообщением и файл доклада не записала.Соберите доклад по последнему сообщению руки из её лога; руку не перезапускайте.
  2. Лаунчер отказал: конверт больше потолкаКонверт разросся на доработке, подстановка плейсхолдеров добавила байты.Проверьте размер готового конверта через wc -c до запуска; конверт больше потолка из раздела 4 режьте до волны.
  3. Рука снята потолком времени без коммитаТикет крупнее потолка или хост под нагрузкой.Поднимите потолок на запуск этого тикета или разрежьте тикет: код с тестами отдельно от мутаций и документации.
  4. Мутации шва стёрли работу рукиgit checkout -- прошёл до коммита.Мутации запускайте только после коммита и push.
  5. Гейт красный на тесте вне диффаЧужой коммит ствола, порядок тестов или нагрузка хоста.Прогоните тот же тест на стволе и в изоляции до любой правки кода.
  6. Гейт красный на проверке времениХост под нагрузкой, тест мерит wall-clock.Сверьте load с числом ядер и повторите тест в изоляции; пропуск гейта без такого повтора не используйте.
  7. Мерж отказал: дерево не совпадает с деревом гейтаСтвол ушёл вперёд, пока шёл гейт, в стволе работает другая сессия.Запускайте гейт и мерж одной цепочкой gate-merge-loop.sh сразу после зелёного ревью.
  8. Фоновая задача гейта пропала без итогаХарнесс убивает фоновые задачи при нехватке памяти хоста.Длинные стадии запускайте под nohup, фоновой задаче оставляйте лёгкий ожидатель маркера.
  9. Ожидатель руки сработал сразу после запускаОн поймал событие прошлой попытки или промежуточный push кандидата.Конец руки ждите по pid-файлу текущей попытки.
  10. Ратчет красный после мержа ствола в веткуЧужой коммит добавил функции без подъёма потолка, или разрешение конфликта чужой стороной потеряло функции ветки.Перемеряйте ратчет после каждого мержа ствола, конфликт ратчета сводите руками.
  11. Тесты упали после нового аргумента функцииЗаглушки тестов не принимают новый именованный аргумент.Сохраните прежнюю форму вызова и до гейта найдите все заглушки этой функции через rg.
  12. Старые тесты упали после смены DoDТесты держат прежнее ожидание.Найдите старое значение по всем тестам через rg и включите эти файлы в узкий прогон.
  13. Проба ревьюера краснаяПроба работает на своей заглушке, а не на настоящем писателе.Сверьте пробу тестом с настоящим писателем до доработки.
  14. Находку закрыли, а соседний вход сломанПравка одного входа функции не покрывает другие входы того же множества.Проверьте соседние входы и края условия.
  15. Третий круг ревью по одному швуТикет держит обязательство между двумя хранилищами без общей транзакции.Остановите круг, вынесите шов отдельным тикетом; дальше решает владелец.
  16. Вердикт прогона противоречит фактуВердикт снят по словам вывода, а слово failed есть и в xfailed.Снимайте вердикт по коду выхода.
  17. Живой DoD: ноль ошибок, а работа не виднаНоль без события ничего не доказывает.Дождитесь события, которое должно было случиться, и запишите его улику.
  18. Ревьюер отвечает 401Сломан общий токен входа или лёг маршрут провайдера.Модели не перебирайте: переключите ревьюера на REVIEWER=opus-headless и повторите позже.
  19. В конверте испорчены общие обозначенияЛаунчер заменяет все вхождения своих плейсхолдеров.Для общих обозначений в тексте конверта берите другие имена.
  20. «Опции нет» по выводу --helpВывод обрезан через head.Проверяйте источник полным проходом.
